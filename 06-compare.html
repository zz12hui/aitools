🎯 按场景选

选 Claude Code，如果你是：

  • ✅ 主要写代码，需要深度代码理解和重构
  • ✅ 喜欢极简，一个终端搞定一切
  • ✅ 已有 Claude 订阅或 Anthropic API Key
  • ✅ 用 VS Code / JetBrains，想 IDE 内集成
    • ✅ 不想折腾配置，开箱即用

# Claude Code 的典型一天
claude -p "Refactor auth module" --allowedTools "Read,Edit,Bash"
claude -p "Review this PR" < pr.diff
claude  # 进入交互模式慢慢聊

选 Hermes Agent，如果你是：

  • ✅ 想在微信/Telegram 上和 AI 聊天
  • ✅ 需要多个平台统一管理（家里 TG、公司微信）
  • ✅ 需要定时任务（每天发报告、监控服务器）
  • ✅ 用国产模型（DeepSeek/Kimi/通义千问）
    • ✅ 喜欢开源可定制
    • ✅ 想教 AI 学新技能

# 晚上自动总结今日 GitHub 动态

❓ 常见问题 (FAQ)

Q1: 两个都装会冲突吗？

不会。它们是完全独立的软件：Claude Code 用 Node.js/npm，Hermes 用 Python/pip。文件、配置、命令全部分开。

Q2: 我就想试试，装哪个最快？

Claude Code。 5 分钟搞定（npm install -g + 配 Key），立刻能写代码。Hermes 更强大但门槛稍高。

Q3: 能用同一个 DeepSeek API Key 服务两个吗？

✅ 完全可以。同一个 Key 可以同时用在 Claude Code 和 Hermes 上，费用统一结算。

Q4: 团队用应该选哪个？

要看场景。个人开发者选 Claude Code（专注编码）。需要统一 AI 入口的团队选 Hermes（多平台 + 多用户 + 定时任务 + 技能共享）。

Q5: 只能装一个，选谁？

写代码为主 → Claude Code。聊天/管理/多平台为主 → Hermes。拿不准就从 Claude Code 开始，入门门槛低，以后再装 Hermes 联动。

Q6: 两个工具的内存/配置会互相覆盖吗？

不会。Claude Code 的东西在 ~/.claude/ 和项目 .claude/，Hermes 的在 ~/.hermes/。井水不犯河水。

Q7: 两个都用 DeepSeek，额度消耗会翻倍吗？

看你怎么用。如果 Hermes 自动帮你派任务给 Claude Code，当然两份调用。但如果只用其中一个，另一个不跑就不花钱。

⚠ 双持用户的特殊注意事项

注意事项详情
别把两个工具的命令搞混claude vs hermes，写 shell 脚本时小心
API Key 可以共用但分开管理更好建议给 Claude Code 和 Hermes 各建一个 DeepSeek Key，方便分别查看用量
Claude Code 的 CLAUDE.md 不影响 Hermes两个工具的记忆/配置互不感知，需要在两边分别设置
联动时需要两个都正常运行Hermes 调 Claude Code 的前提是 Claude Code 已安装且已认证
Git 项目里会多出两个 .claude/ 目录.claude/ 可以提交到 Git（团队共享），.hermes/ 不在项目里
